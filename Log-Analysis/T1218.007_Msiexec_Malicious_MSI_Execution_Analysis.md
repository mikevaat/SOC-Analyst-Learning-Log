## Executive Summary

The analyzed Windows Event Log data reveals a confirmed execution chain involving a suspicious Windows Installer (`.msi`) package that resulted in the deployment and execution of an unauthorized temporary executable.

The execution sequence began with `msiexec.exe` processing an MSI package from a user-controlled temporary directory, followed by the creation of `MSI4FFD.tmp` inside the Windows Installer directory. This temporary executable subsequently spawned `cmd.exe`, which executed `whoami.exe` for system identity discovery.

The process lineage:

`msiexec.exe → MSI4FFD.tmp → cmd.exe → whoami.exe`

represents a highly suspicious execution pattern commonly associated with malicious MSI packages using Windows Installer Custom Actions to execute attacker-controlled code while abusing a trusted Microsoft binary.

Immediate investigation into the origin of the MSI package, payload contents, and potential command-and-control activity is recommended.

# 3. Chronological Reconstruction

The execution trace highlights a clear parent-child cause-and-effect relationship:

### Stage 1: Initial Staging
- At **22:48:58.901**, an initial MSI file (`302a23.msi`) is written to or accessed in the user's temporary directory (`AppData\Local\Temp`).

### Stage 2: Background Service Activation
- Almost immediately after, at **22:48:59.151**, the Volume Shadow Copy Service (`vssvc.exe`) starts up under the SYSTEM context.

### Stage 3: Installation Execution
- At **22:49:07.901**, `msiexec.exe` interacts with another MSI file (`304d1c.msi`) in the `C:\Windows\Installer\` directory.
- Subsequently, it sets an "InProgress" registry key at **22:49:08.432**.

### Stage 4: Payload Detonation
- At **22:49:08.604**, `msiexec.exe /V` spawns a temporary executable (`MSI4FFD.tmp`) directly from the Installer directory.
- This `.tmp` file is unusually labeled as the "ApacheBench command line utility".

### Stage 5: Scripting Engine Load
- Milliseconds later, at **22:49:08.698**, `msiexec.exe` loads `vbscript.dll`, strongly indicating that the MSI package contains VBScript-based Custom Actions.

### Stage 6: Shell Invocation & Discovery
- The `MSI4FFD.tmp` process spawns `cmd.exe` at **22:49:09.276**.
- Approximately three minutes later, at **22:52:27.588**, this command shell executes `whoami.exe`, a standard first step for threat actors confirming their execution context.

# 4. Threat & Anomaly Detection

- **[CRITICAL] Suspicious Process Lineage:** `msiexec.exe -> MSI4FFD.tmp -> cmd.exe -> whoami.exe`. It is highly anomalous for an installer temporary file to spawn an interactive command shell and run reconnaissance utilities.
- **[HIGH] Binary Masquerading:** The file `MSI4FFD.tmp` has a description of ApacheBench command line utility. Legitimate MSI `.tmp` custom actions do not typically bundle third-party load-testing tools, and ApacheBench is not naturally associated with Windows Installer.
- **[MEDIUM] Scripting DLL Load:** Loading `vbscript.dll` during MSI execution is common, but when combined with a suspicious payload drop, it often points to a malicious Custom Action used to execute shellcode or evade initial static detection.
- **[LOW] Volume Shadow Copy Activity:** VSSVC.exe started near the initial MSI event. While this can occur naturally during software installations (creating restore points), it is also heavily associated with ransomware preparing to delete shadow copies. No explicit `vssadmin delete shadows` command is visible in this log snippet, so malicious intent here is possible but unconfirmed.

# 5. Operational & Performance Analysis

- **System Integrity:** There are no indicators of performance bottlenecks, latency spikes, or service failures in the provided data.
- **Operating System Status:** The logs originate from an outdated OS version — Windows 7 (6.1.7601.17514). This represents a severe operational security risk, as the host is fundamentally vulnerable to numerous unpatched exploits.

# 6. Root Cause Hypothesis

### Confirmed Facts
- A user or automated process executed an MSI file originating from a Temp directory.
- The Windows Installer process dropped an executable (`MSI4FFD.tmp`) that contains metadata describing itself as ApacheBench.
- This dropped executable successfully spawned `cmd.exe`.
- The `cmd.exe` process was used to execute `whoami.exe`.

### Inferred Hypotheses
- **[CRITICAL CONFIDENCE] Malicious MSI Execution:** The host was compromised via a malicious MSI package. The use of an MSI file is a common Living-off-the-Land (LotL) technique to bypass Application Control solutions, as `msiexec.exe` is a trusted Microsoft binary.
- **[HIGH CONFIDENCE] Reverse Shell / Interactive Access:** The 3-minute gap between `cmd.exe` creation (22:49:09) and `whoami.exe` execution (22:52:27) suggests manual, interactive keyboard activity by an attacker who caught a reverse shell, rather than a fully automated script which would execute milliseconds later.
- **[MEDIUM CONFIDENCE] VBScript Trigger:** The malicious `.tmp` executable was likely extracted and executed via a VBScript Custom Action embedded within the MSI file, evidenced by the loading of `vbscript.dll`.

# 7. Actionable Intelligence & Remediation

### Immediate Containment Steps:
- **Isolate the Host:** Immediately sever IEWIN7 from the network to prevent lateral movement or data exfiltration. The execution of `whoami.exe` confirms active exploitation.
- **Preserve Volatile Memory:** Capture a RAM image of the host before powering down to recover potential injected shellcode, C2 network connections, and unencrypted staging data.

### Investigation Steps (Pivots):
- **Network Pivot:** Query firewall and Proxy/DNS logs for the exact timeframe (`2019-04-30 22:49:00 - 22:53:00 UTC`) for unusual outbound connections originating from the host's IP address. Look for C2 beaconing.
- **File Forensics:** Locate and acquire the following files for sandbox detonation and static reverse engineering:
  - `C:\Users\IEUser\AppData\Local\Temp\302a23.msi`
  - `C:\Windows\Installer\MSI4FFD.tmp` (or recover it via the provided hashes: SHA256 `17F746D82695FA9B35493B41859D39D786D32B23A9D2E00F4011DEC7A02402AE`)
- **Log Pivot:** Expand the Sysmon search horizon to check for downstream lateral movement tools (`ping`, `net view`, `powershell`, `wmic`) executed by `cmd.exe` after the `whoami` command.

### Security Hardening Recommendations:
- **Decommission Windows 7:** The host operating system is EOL. It must be upgraded to a modern, supported OS.
- **AppLocker / WDAC:** Implement application control rules to prevent `msiexec.exe` from executing packages located in AppData\Local\Temp or other user-writable directories.
