## Executive Summary

A deep forensic analysis of the provided raw binary data identified a fragmented Windows Event Log (`.evtx`) artifact associated with the host **MSEDGEWIN10**. The extracted evidence references the execution of a suspicious executable named **proc_doppel64.exe**, located within the commonly abused directory `C:\ProgramData\`.

The presence of Transactional NTFS (TxF) related structures, including fields such as **TransactionId**, **ResourceManager**, and **NewState**, combined with the suspicious process naming convention, indicates potential use of the **Process Doppelgänging** defense evasion technique. This technique abuses Windows transaction mechanisms to execute a process from a modified file state while reducing traditional forensic visibility.

The observed activity is associated with the user context **IEUser**, suggesting execution occurred under a local user session on the affected endpoint. While the provided fragment does not contain sufficient evidence to confirm a complete compromise chain, the combination of suspicious execution location, transactional file activity, and known defense evasion indicators represents a **high-confidence security concern**.

Further investigation should focus on recovering the complete EVTX source, identifying associated process creation events, validating the binary through malware analysis, and reviewing endpoint telemetry for additional persistence, privilege escalation, or lateral movement activity.

# 4. Threat & Anomaly Analysis

## Finding 1: Execution from Suspicious Directory (C:\ProgramData\)
**Severity:** High
**Analysis:** Legitimate user applications rarely execute directly out of the root of `C:\ProgramData\`. This directory is a world-writable location frequently used by malware to drop payloads to evade standard user-directory monitoring.

## Finding 2: Process Doppelgänging Signature
**Severity:** Critical
**Analysis:** The execution of a file explicitly named `proc_doppel64.exe` combined with security audit templates targeting `TransactionId`, `ResourceManager`, and `NewState` points directly to Process Doppelgänging. This technique allows an attacker to write a malicious payload inside a transactional file (which is never committed to disk), launch a process from it to bypass security controls/AV, and then roll back the transaction to leave no footprint.

# 5. Operational Analysis
- **Log Integrity:** The presence of clean ElfFile and ElfChnk binary signatures confirms the file structure is intact.
- **System Activity:** The operational logs from `Microsoft-Windows-CoreSystem-SmsRouter` imply that SMS/routing network layers or background communication handlers were actively polling or routing entries concurrently with the security audit. No resource exhaustion or database timeouts are present in this specific layer.

# 7. Recommendations & Actionable Next Steps
## Immediate Containment
- **Isolate the Host:** Quarantine the endpoint **MSEDGEWIN10** from the network immediately using your EDR platform to stop potential lateral movement.
- **Kill & Dump Process:** Search for any running processes originating from `C:\ProgramData\proc_doppel64.exe`. If found, capture a memory dump of the process before terminating it to analyze if a hollowed/uncommitted payload is running inside a legitimate process container.

## Investigation Steps
- **Pull Full Security Logs:** Extract the complete `.evtx` file from **MSEDGEWIN10** to resolve the actual timestamp fields and Event IDs (specifically looking for Event ID 4688 for process creation or KTM transaction events).
- **File Carving:** Attempt to retrieve `C:\ProgramData\proc_doppel64.exe`. If the file has been deleted or rolled back via TxF, analyze the USN Journal or MFT transactions for deleted file attributes.

## Hardening & Monitoring
- **Attack Surface Reduction (ASR):** Implement an ASR rule or AppLocker/Windows Defender Application Control (WDAC) policy to explicitly prevent executables from running directly out of `C:\ProgramData\` or its subfolders unless explicitly whitelisted.
- **EDR Tuning:** Ensure your Endpoint Detection and Response tools are configured to actively alert on unexpected Transactional NTFS (TxF) requests accompanied by rapid rollbacks.
